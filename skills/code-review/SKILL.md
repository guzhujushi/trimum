# 代码审阅

1. **先看边界**：改动文件是否都在允许清单里？有没有夹带的重排、格式化、无关行？
2. **再看语义**：逐个 hunk 问「这行为什么必须改」；找不到理由的就是噪音。
3. **找回归**：原有行为有没有被削弱？错误路径（没跑成、被拒、超时）是否仍如实报告？
4. **给复现**：发现问题时给**最小复现**（输入 → 实际 → 期望），不要只说「看起来不对」。
